# 文件操作日志

本次只增加文件日志和日志查看页面。工程中的“运行文件”指在文本编辑器中打开文件、在画图应用中读取 BMP，以及播放 WAV 音频。

## 使用

1. 在 Keil 中打开 `MDK-ARM/Computer_Sim.uvprojx`，重新编译并下载到开发板。工程已加入 `UI/SystemLog.c/.h`。
2. 登录桌面，在 Files 中双击打开文本、BMP 或 WAV 文件；WAV 打开播放器后，还需点击播放按钮才开始播放。
3. 保存文本或画图，或在 Files 中创建文件、文件夹。
4. 返回桌面打开 Logs。最新记录排在前面，每页最多八条；列表可滚动，Newer/Older 切换页，Clear 立即清空现有记录。

## 记录内容

- Open request：用户请求打开文件，尚未表示读取成功。
- Open：文本读取和页面打开结果、BMP 加载结果，或 WAV 播放器页面打开结果。WAV 的 Open OK 不表示音频已播放成功。
- Play request：请求播放；命令被拒绝会另记失败。
- Playing：音频已经启动。
- Finished / Stopped / Track replaced：播放正常结束、被用户停止、被另一个播放请求替换。
- Playback error：读取、格式解析、缓冲区或 DMA 等实际播放错误；从音频任务记录，不依赖播放器页面保持打开。
- Save / Create file / Create folder：保存、创建操作及其结果。新画图首次保存记为 Create file，以后保存记为 Save。

每条记录显示操作发生时的开机时长、完整路径、结果文字及十六进制结果码。失败记录显示为红色。无修改时点击保存不产生保存记录。文件系统调用失败时即使目录中已存在目标，日志仍保留实际返回的错误码，方便定位。

## 存储和接口

日志及管理信息保存在外部 SRAM，约 17 KB，保留最近 64 条，满后自动覆盖最旧记录。重启或断电清空，未写入 SD 卡。关闭 Logs 后继续记录。

初始化位于 `Core/Src/main.c`，在外部 SRAM 内存池初始化完成后、任务启动前调用 `SystemLog_Init()`。记录和读取通过短临界区保护，接口只供任务上下文调用。

新接入点通常只需要一行，放在最终返回码确定之后：

```c
SystemLog_Write(SYSTEM_LOG_SAVE, file_path, result);
```

`result` 为 0 表示成功，1～19 保留 FatFs 错误码，0x80～0x83 保留播放器错误码，0x100 以上用于内存、页面或命令提交等应用错误。
